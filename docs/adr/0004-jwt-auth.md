# 0004: 認証にJWTを採用する

## Status

Accepted

## Context

タスク管理APIはユーザーごとにデータを分離する必要があり、何らかのステートレスな認証機構が必要だった。セッション管理を自前実装する案とJWTを使う案を検討した。

## Decision

認証には`golang-jwt/jwt/v5`によるJWTを採用する。`POST /auth/login`でHS256署名のアクセストークンを発行し、以降のリクエストは`Authorization: Bearer <token>`ヘッダーで認証する。検証・ユーザーID抽出は`internal/auth`の`RequireAuth`ミドルウェアに集約している。

## Consequences

- 自前のセッション管理(セッションストア・Cookie管理)が不要になり、サーバーをステートレスに保てる
- 自前でトークンの生成・検証ロジックを書くよりバグが少なく安全、という判断のもとで確立したライブラリを採用した
- リフレッシュトークンの仕組みは今回のスコープでは実装していない(トークン有効期限は1時間固定、`internal/config`で管理)
- メール確認・パスワードリセットは今回のスコープ外([0005](./0005-bcrypt-password-hashing.md)と合わせて意図的に省略)
