# 0002: Webフレームワークを使わず`net/http`のみで実装する

## Status

Accepted

## Context

DevOpsキャンプ最終課題の課題要件で、Webフレームワーク(gin, echo等)を使わず標準ライブラリのみで実装することが明示的に指定されていた。Go 1.22以降の拡張`http.ServeMux`はメソッド(`GET`/`POST`等)とパスパターン(`/tasks/{id}`)を使ったルーティングをサポートしており、フレームワークなしでも最低限のルーティングは組める状態だった。

## Decision

ルーティング・ミドルウェア相当の処理をすべて標準ライブラリ`net/http`のみで実装する。認証チェックは`http.HandlerFunc`を受け取り`http.HandlerFunc`を返すデコレータ関数(`internal/auth.RequireAuth`)として自前実装する。

## Consequences

- サードパーティのWebフレームワークに依存しないため、依存関係が少なく学習内容が標準ライブラリの理解に直結する
- ミドルウェアチェイン・ルーティング・エラーハンドリングの共通化(`internal/httpx`)を自前で用意する必要があり、フレームワークが提供する機能を手で書く分の実装コストが発生する
- パスパラメータの取得は`r.PathValue("id")`(Go 1.22+)に依存するため、Goのバージョンを一定以上に保つ必要がある
