# 0007: タスク階層をparent_idの自己参照で表現する

## Status

Accepted

## Context

アプリのテーマ上、子タスク・孫タスクの作成をサポートする必要がある。階層構造の持たせ方として、自己参照FK・別テーブルでの親子関係管理(隣接リストとは別の閉包テーブル等)・階層の深さを固定する設計、などを検討した。

## Decision

`tasks.parent_id`が自身の`tasks.id`を参照する自己参照外部キー(`ON DELETE CASCADE`)で階層を表現する。階層の深さはDB側では制限しない。必要になった場合はアプリケーション側でバリデーションする方針とする。

## Consequences

- スキーマは`tasks`テーブル1つで完結し、閉包テーブルのような追加テーブルが不要
- 親タスクを削除すると子タスク以下がカスケード削除される(`GET /tasks/{id}`のレスポンスで子タスク一覧を返す実装と対応)
- 階層の深さに理論上の制限がないため、無制限に孫・曾孫…と作られた場合のパフォーマンスや表示崩れは現状バリデーションしていない。深さ制限が必要になった場合はハンドラ層(`internal/handlers/tasks.go`のCreate)への追加実装で対応する
